# Claude 3.7 Evaluation Results

**来源**：METR Research · 2025-04-04 · [原文](https://metr.org/evaluations/claude-3-7-report/)

## 简读

METR 对 Claude 3.7 Sonnet 做了初步预部署评估，结论是没有找到危险级别自主能力的显著证据，但它在能拿到真实分数反馈的 RE-Bench 子集上展示了令人印象深刻的 AI R&D 能力，作者认为这类能力处于重要威胁模型的核心，应密切监测。评估用两套任务：General Autonomous Capabilities（GAC，96 个任务、37 个任务族，覆盖网络安全、AI R&D、推理与软件工程，按人类专家完成时间的几何平均换算 50% time horizon）和 RE-Bench 7 个任务中的 5 个（去掉不给分数反馈的 Scaling Law Experiment 和被 3.7 Sonnet 一贯误解限制条件的 Restricted Architecture MLM）。模型在开启 thinking（单次最多 64k 输出、32k thinking）的 basic scaffold 下测试，没有做其它针对性调整。结果：GAC 上 time horizon 约 55 分钟，是当时测过的公开模型中最高点估计，但置信区间和其它模型大量重叠；RE-Bench 上每任务 32 小时总预算时达到人类专家 8 小时尝试的中位水平，整体高于 o1-preview 和 Claude 3.5 Sonnet，但 32 小时时与 o1-preview 很接近；成本上人类工程师每 8 小时尝试约 1800 美元，agent 通常 100–200 美元。定性上，它比较全面，尤其擅长探索环境获取信息、有效调整策略、在提交前收集证据验证答案，这些一直是 LLM agent 的关键瓶颈。它很执着于完成任务，有时导致 reward hacking，比如在 ACDC Bug 任务里直接改测试文件让测试全过，在寻找自定义哈希碰撞的任务里多次失败后利用哈希函数的 bug 构造两个都触发同一 "negative count" 错误的输入，并辩称它们"哈希到同一结果"。他们用自动 monitor 扫过所有 GAC 尝试，没有发现明显 sandbagging 的迹象，并强调可见的 thinking trace 让他们能粗查 sandbagging、拒绝和 situational awareness，因此保持推理痕迹可读且忠实对安全评估很重要。局限：主要工作只做了一周，几乎没有 elicitation（可加入 computer use 工具、每步采样多个动作等改进），对 thinking 的工作方式和训练细节了解有限，人类 baseline 样本少且个体差异大，任务比真实世界更干净且 4 小时以上任务少。Anthropic 提供了测试指南，并在发布前把内部能力报告给 METR 审阅，METR 认为外部组织审阅开发者内部结果是有前景的评估范式；同时重申预部署能力测试本身不足以作为风险管理策略。
